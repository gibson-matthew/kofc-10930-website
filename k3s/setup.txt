k3s setup

Run this on the k3s machine from a copy of the repo. kubectl is /usr/local/bin/kubectl. Use sudo; a normal user cannot read /etc/rancher/k3s/k3s.yaml. Do not commit passwords or tokens. Pick one route for the public hostname. Do not use both on the same name.

Shared

1. Install k3s.

    curl -sfL https://get.k3s.io | sh -
    sudo kubectl get nodes

The node should say Ready.

2. Create the namespace.

    sudo kubectl apply -f k3s/namespace.yaml

3. Publish the image, then set the image line.

Push to main. Actions runs only on that push. A merged pull request creates it. The pull request alone does not. Wait until "Publish image" is green. A failed run does not push a tag. The address is ghcr.io/<github-user-or-org>/<repo-name>:latest. Replace the placeholders with the real owner and repo name, both lowercase. The package appears after the first successful push to main. The workflow also tags the full git SHA. Use latest unless you pin that SHA. In k3s/app.yaml, replace the image line. Do not leave your-github-username in the file you apply.

If the GHCR package is private, the app pod stays in ImagePullBackOff until the node can log in. Make the package public, or create a pull secret from a GitHub personal access token with read:packages. The namespace must exist. Do not commit the token.

    sudo kubectl create secret docker-registry ghcr \
      -n koc10930 \
      --docker-server=ghcr.io \
      --docker-username=YOUR_GITHUB_USERNAME \
      --docker-password='THE_TOKEN'

Uncomment imagePullSecrets in k3s/app.yaml (name: ghcr) and apply k3s/app.yaml again. "not found" or "manifest unknown" means the tag was never pushed or the name does not match. "unauthorized" or "denied" means the package is private and this secret is missing.

    sudo kubectl describe pod -n koc10930 -l app=koc10930

4. Create the app Secret and ConfigMap.

Edit k3s/secret.yaml on the server. It is Secret koc10930-app. Use one password in both places. The host name postgres is the Service from k3s/postgres.yaml.

    DATABASE_URL: "postgresql://koc10930:THE_PASSWORD@postgres:5432/koc10930"
    POSTGRES_PASSWORD: "THE_PASSWORD"

POSTGRES_USER, POSTGRES_HOST, POSTGRES_PORT, and POSTGRES_DB already match that database. REDIS_URL is already redis://redis:6379/0. Replace JWT_SECRET with a value you do not commit:

    python3 -c "import secrets; print(secrets.token_urlsafe(48))"

Leave these empty until you want email routing or sending. Empty leaves those features off. Sign-in still works. They are the Cloudflare and mail keys from .env.example:

    CLOUDFLARE_API_TOKEN
    CLOUDFLARE_EMAIL_TOKEN
    CLOUDFLARE_ACCOUNT_ID
    CLOUDFLARE_ZONE_ID
    MAIL_FROM
    MAIL_OFFICER_TO

In k3s/configmap.yaml set CORS_ORIGINS to https:// and the public hostname. COOKIE_SECURE is already true. CLOUDFLARE_ROUTING_DOMAIN stays the zone you actually route, or mistymountains.dev while that is the testing domain. VITE_API_BASE is a build arg, left empty, not a runtime key.

    sudo kubectl apply -f k3s/secret.yaml
    sudo kubectl apply -f k3s/configmap.yaml

5. Apply Postgres, Redis, and the app. The app waits until Postgres accepts connections.

    sudo kubectl apply -f k3s/postgres.yaml
    sudo kubectl apply -f k3s/redis.yaml
    sudo kubectl apply -f k3s/app.yaml
    sudo kubectl get pods -n koc10930

postgres and redis should become Running. After each later push to main, the new :latest image is not pulled until you recreate the pod:

    sudo kubectl rollout restart deployment/koc10930 -n koc10930
    sudo kubectl rollout status deployment/koc10930 -n koc10930

Route 1 — Cloudflare (recommended)

No public port 80 or 443 on the node. Visitors use HTTPS at Cloudflare. SSL/TLS mode is Full (strict). cloudflared dials out and forwards HTTP to the Service.

Do not apply k3s/issuer.yaml or k3s/ingress.yaml. If the Ingress is already on the cluster, delete only that route:

    sudo kubectl delete -f k3s/ingress.yaml

In Cloudflare: Networking, Tunnels. Create a tunnel, name it council-10930, choose Docker, and copy only the token (the eyJ value). Do not run the install command. On that tunnel, add a public hostname. The hostname is the name people type. It is not a Secret. Service type HTTP. URL:

    http://koc10930.koc10930.svc.cluster.local:8080

Do not also add an A or AAAA record for that name to this node. Store the token as Secret koc10930-cloudflared, key tunnel-token:

    sudo kubectl create secret generic koc10930-cloudflared \
      -n koc10930 \
      --from-literal=tunnel-token='PASTE_THE_TUNNEL_TOKEN_HERE'
    sudo kubectl get secret koc10930-cloudflared -n koc10930
    sudo kubectl apply -f k3s/cloudflared.yaml
    sudo kubectl rollout status deployment/cloudflared -n koc10930

Set the zone SSL/TLS mode to Full (strict).

Confirm: deployment/cloudflared is Running, and curl -fsS https://YOUR_HOSTNAME/api/health returns {"ok":true}.

Route 2 — Port forwarding

k3s Traefik already listens on the node. This route publishes that listener. Do not also run Route 1 for the same hostname.

Replace council.example.com in k3s/ingress.yaml (both host lines and the TLS host) with the public hostname. Open the ports:

    sudo ufw allow 80/tcp
    sudo ufw allow 443/tcp

HTTPS is terminated by Traefik using Secret koc10930-tls. The checked-in issuer is Let's Encrypt DNS-01 through Cloudflare. In k3s/issuer.yaml, spec.acme.email is the inbox for certificate expiry notices. It is not a member role address. Replace you@example.com before you apply the file.

Install cert-manager, then create a never-expiring Cloudflare token. Permissions: Zone, DNS, Edit; and Zone, Zone, Read. Limit it to this zone. That token is not CLOUDFLARE_API_TOKEN and not the tunnel token.

    sudo kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.21.3/cert-manager.yaml
    sudo kubectl wait --namespace cert-manager --for=condition=Available deployment --all --timeout=180s
    sudo kubectl create secret generic koc10930-cloudflare-dns \
      -n koc10930 \
      --from-literal=api-token='PASTE_THE_TOKEN_HERE'

Do not apply k3s/cloudflare-dns-secret.yaml after this. That file is empty and would wipe the token. Apply the issuer before the Ingress:

    sudo kubectl apply -f k3s/issuer.yaml
    sudo kubectl apply -f k3s/ingress.yaml

Point DNS at the node. The address is the public IP, not a private 10.x or 192.168.x address:

    curl -4 ifconfig.me

Add an A or AAAA record for the hostname. If the record is proxied by Cloudflare (orange cloud), set SSL/TLS to Full (strict). A grey-cloud record exposes the node directly and does not get that check. Without Cloudflare, this issuer cannot obtain a certificate. Traefik still terminates HTTPS only when Secret koc10930-tls holds a certificate browsers trust.

Watch the certificate. If it stays False, the usual causes are an empty api-token, a token that cannot edit DNS for this zone, or a hostname outside that zone. Then delete the Certificate and apply the Ingress again.

    sudo kubectl describe certificate koc10930-tls -n koc10930
    sudo kubectl delete certificate koc10930-tls -n koc10930
    sudo kubectl apply -f k3s/ingress.yaml

Confirm: certificate koc10930-tls is Ready, and curl -fsS https://YOUR_HOSTNAME/api/health returns {"ok":true}. Port 80 only redirects to HTTPS.
