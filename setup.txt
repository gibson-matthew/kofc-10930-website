Get k3s serving this site on HTTPS

The hostname used below is council.example.com. Replace it in k3s/ingress.yaml (both Ingress hosts and the TLS host) and in k3s/configmap.yaml (CORS_ORIGINS). Replace the email in k3s/issuer.yaml with a mailbox you control. Replace ghcr.io/example/kofc-10930-website in k3s/app.yaml with the image name Actions prints.

1. Install k3s on the server

    curl -sfL https://get.k3s.io | sh -
    sudo kubectl get nodes

  Traefik is included and listens on ports 80 and 443. Open those ports on the host firewall. kubectl on the server is /usr/local/bin/kubectl. If your user cannot read the k3s kubeconfig, run the commands with sudo.

2. Install cert-manager

    sudo kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.21.3/cert-manager.yaml
    sudo kubectl wait --namespace cert-manager --for=condition=Available deployment --all --timeout=180s

3. Create the namespace and the app Secret

    sudo kubectl apply -f k3s/namespace.yaml

  Edit k3s/secret.yaml on the server, not in git. Replace change-me in POSTGRES_PASSWORD, and put the same password in DATABASE_URL. Replace JWT_SECRET with a long random string. Leave the Cloudflare app tokens empty until you want email routing or sending.

    sudo kubectl apply -f k3s/secret.yaml
    sudo kubectl apply -f k3s/configmap.yaml

4. Create the Cloudflare certificate Secret

  In the Cloudflare dashboard, create an API token that does not expire.
  Permission: Zone / DNS / Edit, and Zone / Zone / Read, limited to the zone of the site hostname.
  This token is only for the certificate. Do not reuse it as CLOUDFLARE_API_TOKEN.

    sudo kubectl create secret generic koc10930-cloudflare-dns \
      -n koc10930 \
      --from-literal=api-token='PASTE_THE_TOKEN_HERE'

  Do not commit that command or the token. Do not apply k3s/cloudflare-dns-secret.yaml after this. That file is an empty placeholder and would wipe the token.

5. Apply the rest of the manifests

    sudo kubectl apply -f k3s/postgres.yaml
    sudo kubectl apply -f k3s/redis.yaml
    sudo kubectl apply -f k3s/app.yaml
    sudo kubectl apply -f k3s/issuer.yaml
    sudo kubectl apply -f k3s/ingress.yaml

  The app waits until Postgres accepts connections, then reads its settings from the Secret and ConfigMap.

6. Let the cluster pull the image

  Push to main. When the Publish image workflow is green, the image is on GHCR.
  If the GitHub repo is private, open the package on GHCR and set it to Public. That is the free pull path.
  To keep it private instead, create a GitHub personal access token with read:packages and:

    sudo kubectl create secret docker-registry ghcr \
      -n koc10930 \
      --docker-server=ghcr.io \
      --docker-username=YOUR_GITHUB_USERNAME \
      --docker-password='THE_TOKEN'

  Then uncomment imagePullSecrets in k3s/app.yaml and apply that file again.

  Restart after each push to main:

    sudo kubectl rollout restart deployment/koc10930 -n koc10930
    sudo kubectl rollout status deployment/koc10930 -n koc10930

7. Point the domain at the node

  In Cloudflare DNS, add an A record (or AAAA) for the site hostname to the k3s node's public IP.
  Leave the record proxied (orange cloud). Do not use a grey-cloud record for the public site.

8. Set Cloudflare SSL to Strict

  SSL/TLS encryption mode: Full (strict).
  Wait until the certificate exists:

    sudo kubectl describe certificate koc10930-tls -n koc10930

  Ready=True means Let's Encrypt issued a certificate and Traefik is serving it.

9. Confirm HTTPS

    curl -fsS https://council.example.com/api/health

  Expect {"ok":true}. Open https://council.example.com in a browser. The public page is the same read-only site. http://council.example.com should redirect to https and should not serve the app.

Runtime environment the container expects

  From Secret koc10930-app: DATABASE_URL, POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_HOST, POSTGRES_PORT, POSTGRES_DB, JWT_SECRET, REDIS_URL, CLOUDFLARE_API_TOKEN, CLOUDFLARE_EMAIL_TOKEN, CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_ZONE_ID, MAIL_FROM, MAIL_OFFICER_TO.
  From ConfigMap koc10930-config: COOKIE_SECURE, COOKIE_SAMESITE, CORS_ORIGINS, CORS_ORIGIN_REGEX, UPLOAD_DIR, REDIS_MAXMEMORY, REDIS_MAXMEMORY_POLICY, MAIL_ENABLED, CLOUDFLARE_ROUTING_DOMAIN.
  Build arg, not a runtime variable: VITE_API_BASE. Leave it empty.

  MAIL_ENABLED stays false until sending is configured. Empty routing and sending tokens leave those features off. Sign-in, edits, and the cache still use Postgres and Redis.
